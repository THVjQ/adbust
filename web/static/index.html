Do not use a Mac. adbust only works on a Windows 10, Windows 11 or Linux PC. Move the phone to one of those and open this page there in Chrome or Edge.

Open this on a PC

Plug the phone into a Windows 10/11 or Linux PC with a USB cable and open this page there in Chrome or Edge. Not on a Mac.

Use Chrome or Edge

This browser can't talk to USB devices, so it can't reach the phone. Open this page in Google Chrome or Microsoft Edge on Windows 10/11 or Linux, plug the phone in, and come back.

Why doesn't Firefox or Safari work?

adbust connects to your phone straight from the web page using a browser feature called WebUSB. It lets a trusted page you open ask permission to talk to a USB device — here, the phone's debugging connection — so adbust can list apps and remove the bad ones without installing anything.

Only Chromium-based browsers support WebUSB: Chrome, Edge, Brave and Opera. Firefox and Safari have chosen not to add it on security grounds, so there's no way for a page to reach USB in them — it isn't something adbust can switch on. Phones and tablets can't be the controller either, and macOS blocks the USB access this needs, so a Mac won't work even in Chrome.

If you're stuck on Firefox or a Mac, the desktop version of adbust talks to the phone through the computer's own tools instead of the browser, so the browser you use no longer matters.

Plug in the phone

  1. On the phone: Settings → About phone → Software information, tap Build number 7 times.
  2. Settings → Developer options → USB debugging on.
  3. Plug it into this PC PC with a USB cable, then press the button and pick the phone.

Only needed the first time. After that, plugging the phone in is enough.

Phone not in the list?
  • Close anything else that talks to phones: adb, Android Studio, scrcpy, Samsung Smart Switch. Only one program can hold the connection. On Linux run adb kill-server.
  • Unlock the phone and set the USB mode to File transfer.
  • Try another cable. Charge-only cables don't carry data.
  • Windows: if it still never appears, a phone-maker USB driver may own the connection. Removing that driver in Device Manager lets Windows use its built-in one.
  • Linux: your user needs access to the USB device. Installing android-tools (Fedora) or android-sdk-platform-tools-common (Debian/Ubuntu) adds the rules.

Other things worth knowing

Freeze vs uninstall, device admins, and manual steps

Freeze instead of remove: if you're not sure about an app, freezing it (pm disable-user) stops it running but keeps it, and it's undone with pm enable. Uninstalling a pre-installed app for this user (pm uninstall --user 0) survives reboots and can be restored with cmd package install-existing.

Device admins: an app registered as a device admin can't be uninstalled until admin is removed. The “Open on phone” button above tries to drop it, then opens the app's page on the handset so you can turn admin off under Settings → Security → Device admin apps.

Has to be done on the phone itself: browser site notifications (Chrome / Samsung Internet), checking Play Protect is on, and Family Link for a child's phone.

Brand quirks: on Oppo/Realme/OnePlus turn on Developer options → “Disable permission monitoring”, on Xiaomi enable USB debugging (Security), and on Samsung turn Auto Blocker back on when you're done — otherwise some of these commands are silently blocked.

Run this on the phone?

About to run as an adb shell command on the connected phone. It runs with the same power adbust uses — a wrong command can disable apps, change settings or delete data, and there's no undo. Only run commands you understand.

When and how to use this

Use it for: checking something the buttons don't cover, or applying a one-off fix you've been given. The reply appears in the log.

Safe, read-only examples: getprop ro.build.fingerprint, dumpsys battery, pm list packages -3, settings get secure enabled_accessibility_services.

Be careful with anything using rm, pm uninstall, pm clear, reboot, or settings put — these change or remove things for good.
